# Hardware notes (SSH banner and datacenter Notes)

`roles/proxmox_hardware_notes/` writes one short "at a glance" summary of the GPUs and storage of `pve-00` to two places, and regenerates it on every `task apply`, so new, moved or re-assigned hardware shows up without editing anything:

1. an sshd **pre-login banner** (`/etc/ssh/pve-hardware-banner`, served through the drop-in `/etc/ssh/sshd_config.d/20-pve-hardware-banner.conf`), and
2. a **managed block in the datacenter Notes** (Datacenter > Summary > Notes; stored as `description` in `/etc/pve/datacenter.cfg`).

Illustrative layout (the real text is shown by `task hardware-notes-plan`):

```text
pve-00 hardware at a glance (generated by Ansible - do not edit)

GPU
  NVIDIA GeForce GT 710        -> used by the host (nouveau)
  NVIDIA Quadro P2000          -> passed through (vfio-pci) to VM 4095 k8s-wrkr-01-gpu

STORAGE
  SAMSUNG MZVKW1T0HMLH-000L7   1.0 TB NVMe  -> host ZFS pool rpool (storage local-nvme)
  HGST HDS724040ALE640         4.0 TB HDD   -> host ZFS pool slow (storage local-hdd)
  CT500MX500SSD1               500 GB SSD   -> passed through to VM 4096 k8s-wrkr-02 (scsi2)
```

## Where the information comes from

| Item | Source |
| --- | --- |
| Disks present, model, size, SSD/HDD/NVMe | Ansible facts (`ansible_facts['devices']`). Only whole SATA/virtio/NVMe disks with a non-zero size are listed; zvols, loop devices, optical drives and empty card readers are not. |
| GPU model and the driver bound to it | `lspci -D -vmm -nn -k` (PCI class 03xx). Driver `vfio-pci` means "reserved for passthrough"; anything else is shown as used by the host. |
| Which VM owns a passed-through GPU | `hostpci*` lines in `/etc/pve/qemu-server/*.conf`, resolved through `/etc/pve/mapping/pci.cfg` when a mapping is used. |
| Which VM owns a passed-through disk | `scsi/sata/virtio/ide*` lines that point at `/dev/...` (for example `/dev/disk/by-id/...`) in the VM configs; the link is resolved to its kernel disk. |
| Which disk backs a ZFS pool and Proxmox storage | `zpool status -P` and the `zfspool:` entries of `/etc/pve/storage.cfg`. |
| Other host use | `/proc/mounts` and `/proc/swaps`. A disk with none of the above is shown as `unused`. |

The read-only helper is `roles/proxmox_hardware_notes/files/hardware_inventory.py`; the layout is `templates/summary.j2`. Only the **current** VM configuration is read: `[PENDING]` and snapshot sections are ignored.

## Behaviour and limits

- **The banner is pre-authentication**, so anyone who can reach port 22 sees it. It lists models and sizes only: no serial numbers, addresses or credentials. Set `proxmox_hardware_notes_banner: false` to skip it.
- **Datacenter Notes**: only the text between `<!-- BEGIN proxmox_hardware_notes ... -->` and `<!-- END proxmox_hardware_notes -->` is managed. Anything else already in the Notes is kept; edits inside the markers are overwritten on the next apply. Set `proxmox_hardware_notes_datacenter: false` to skip it.
- sshd honours the first `Banner` directive it reads. The role reads the effective configuration with `sshd -T` and **fails** if another directive wins, instead of silently doing nothing. sshd is reloaded only when the drop-in changes; banner text changes need no reload.
- Disks handed to a VM through a Proxmox storage (a virtual disk) are not "passed through" and are not detected as such. Hardware that is used in a way none of the sources above can see appears as `unused`.
- The summary reflects the state **at the last apply**. Re-run `task hardware-notes-apply` after changing hardware or VM assignments.

## Validation

```sh
task hardware-notes-plan     # read-only; prints the rendered summary and whether the Notes would change
task hardware-notes-apply
ssh pve-00 true              # the banner is printed before authentication
```

Then open Datacenter > Summary and confirm the Notes panel. Unit tests: `python3 -m unittest tests.test_hardware_notes`.

## Rollback

Delete `/etc/ssh/sshd_config.d/20-pve-hardware-banner.conf` and `/etc/ssh/pve-hardware-banner`, reload sshd, and remove the marked block from the datacenter Notes in the web UI (or `pvesh set /cluster/options --delete description` if nothing else is stored there). Set both role switches to `false` to stop the role from recreating them.

## Assumptions

- Debian 13 with the stock `Include /etc/ssh/sshd_config.d/*.conf` and the `ssh` systemd unit.
- `pvesh get/set /cluster/options` works on a standalone node (the `description` option is documented in `datacenter.cfg(5)`).
